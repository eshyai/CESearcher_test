# 化工行业资讯智能体：架构与可行性

## 结论

现有项目适合作为基础，后端已有 FastAPI、PostgreSQL、用户认证、定时采集和知识库，前端已有资讯页与登录态。新增功能应以“可审计的反馈学习”作为核心，避免让模型直接、不可逆地改写知识库。

## 目标架构

```text
关注碎片（行业/客户/工艺/技术/产品）
          │
          ▼
查询规划 ──> 多来源搜索 ──> 去重/抽取/来源留痕 ──> 资讯库
                                                   │
                    用户反馈（兴趣、相关性、备注） ◀─┘
                              │
                              ▼
                 透明权重更新 + 个性化排序
                              │
                              ▼
          共享知识库（成员角色、修订号、软删除、审计日志）
```

## 数据与权限边界

- `FocusTopic`：每位用户的关注主题和可见权重；主题类型明确，避免把所有偏好压成不可解释的向量。
- `NewsFeedback`：保存每条资讯的兴趣、相关性和备注；同一用户对同一资讯只保留一条当前状态。
- `KnowledgeBaseMember`：`viewer` 可查看，`editor` 可新增和修改，`manager` 可管理成员及删除/恢复。
- `KnowledgeAuditLog`：记录共享知识库的重要变更。
- 知识库删除采用软删除；修订号用于并发控制和后续恢复。

## 学习策略

第一阶段使用有界指数更新：`new = clamp(0.85 × old + 0.35 × feedback, -2, 2)`。排序综合主题权重与 30 天新鲜度。该方法样本少时稳定、可解释、可回滚。积累足够反馈后，再增加团队级模型、嵌入相似度和离线评估。

## 搜索方案

保留现有 Serper/博查适配器，并抽象为可替换搜索提供方。可选 OpenAI Responses API `web_search` 作为第二适配器，用于实时网页搜索、域名过滤和完整来源列表。所有结果都必须保留原始 URL、发布时间、采集时间和来源。

## 分阶段交付

1. 已开始：关注主题、反馈事件、可解释权重、个性化排序、前端反馈入口、共享成员角色、审计与软删除。
2. 下一步：主题管理界面、OpenAI 搜索适配器、资讯去重指纹、失败重试与来源白名单。
3. 生产化：Alembic 迁移、组织/团队模型、OIDC/企业登录、任务队列、指标监控、备份恢复和权限测试。

## 风险判断

- 技术可行性：高。现有栈覆盖主要基础设施。
- 数据质量风险：中高。搜索摘要可能截断或误判，必须保留引用并区分“事实、推断、模型标签”。
- 权限风险：中。当前项目原始实现是创建者私有，需要经过完整 RBAC 测试后再对生产数据开放共享。
- 运维复杂度：中高。当前依赖 PostgreSQL、Redis、Milvus、Elasticsearch、MinIO；MVP 可先关闭非必要组件，生产环境再按负载启用。
